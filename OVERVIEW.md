session-recovery tracks running Paseo turns and continues eligible unfinished sessions after a daemon restart. Above each session's composer, Goal previews the current objective. Press the text to edit it in a desktop popover or a mobile bottom sheet. Codex and OpenCode have separate native pause and resume controls. Viewing a goal never starts work or selects it for continuation.

Codex edits preserve its goal token budget and usage. Its pause and resume buttons use the owning Paseo connection, and a current turn may finish after pausing. OpenCode edits preserve the focused goal ID, turn/token/time budgets, usage, and history, and activate paused or blocked goals. Its controls require an idle session. OpenCode resume opens the editor with a short budget-reset notice above Resume. That action explicitly starts a new native budget window. Both native goal loops may start work after saving or resuming. Exhausted limits require native review. OpenCode requires opencode-goal-plugin's registered Goal mode, native /goal command, and version 1 session state; its command and agent must reference a valid configured model.

Claude uses Replace & start. Its native /goal command replaces the condition, immediately starts a turn, and resets the goal timer, evaluated turn count, and token-spend baseline. It has no separate goal token budget or supported explicit pause/resume command. Reported tokens are from the last native evaluation. Its native command must be allowed by workspace trust and hook policy. Claude edits require an idle session. Claude and OpenCode conditions accept up to 4,000 characters. Codex accepts up to 16,000. OMP/Pi can display goal text from structured history after explicit inspection. OMP's current goal RPC has no objective update, and this Paseo plugin connection does not expose its native pause/resume operations.

The full goal screen is also available through /goal, /goal edit, /goal-edit, or View or edit this session's goal in the Command Center. Completed goals, exhausted limits, pending approvals, uncertain delivery, and unavailable state are read-only. Saving or controlling a goal rechecks its identity and session. Tickets expire after five minutes and are used once. Native control intent is recorded before submission; an unconfirmed result requires review and is not automatically retried. Paseo has no atomic conditional goal update, so a concurrent action can still race the final check.

Paseo continuation is a separate optional control under the editor's Details and on recovery cards. It starts off globally, and each current objective also needs an explicit selection. Enable Continue selected goals in settings to use it. The default delay is 60 seconds with 10 continuations per objective. A changed objective or explicit native pause/resume clears the fallback selection. Turning the fallback selection off cancels its pending messages while keeping interruption recovery available. It does not pause a provider's native goal loop. Explicitly selecting a blocked Codex goal can resume it with its existing limits; direct session stops, pending input, and exhausted limits prevent that path. Native pauses, blockers, completions, and unknown state never resume automatically. The plugin cannot independently verify that a provider's completed goal was achieved.

Automatic interruption recovery is on by default for main sessions, with a 60-second initial delay, up to three attempts per interruption, and a 24-hour recovery window. Delay doubles after each attempt, up to 15 minutes. Subagent recovery and recognized temporary provider error retries can be enabled separately. Recovery starts a turn in the existing conversation with its current provider and settings. It asks the agent to inspect work before repeating actions; it cannot restore an interrupted process. Direct stops, questions, and approvals block automatic recovery. The recovery screen offers review, manual continuation previews, exclusions, history, and settings. The sidebar shortcut appears on desktop and web; on mobile use Open session-recovery in the Command Center. Composer controls are available on all clients.

Requires a macOS or Linux daemon on stable Paseo 0.11.4 through 0.12.x and a provider with saved history. Only Paseo-managed sessions are covered. The paired session-janitor 0.1.2+ protects pending recovery and continuation from cleanup; other cleaners do not read those protections. Goal entries are registered from session metadata. Only mounted supported-provider composers read native previews, with up to four concurrent checks per client. These reads never restore conversations. OMP/Pi history inspection is explicit and bounded to 2,000 canonical entries. Claude reads only the selected transcript's current parent chain, bounded to its last 8 MiB. CLAUDE_CONFIG_DIR in the provider environment is supported. OpenCode reads the focused goal's bounded version 1 per-session snapshot, using the project-local default or OPENCODE_GOAL_STATE_PATH. Missing, changing, malformed, incomplete, or outdated native state requires review.

Native previews are kept briefly in memory. Goal objectives and command tickets are not saved in the recovery journal. Local owner-only files keep session metadata, goal fingerprints, state, selections, attempt counts, and recent outcomes. Continuations and explicit native commands use the existing session and provider with normal provider usage and billing. Claude's native loop owns its continuation; the plugin does not send additional fallback messages while its goal is active. OpenCode native continuation claims and child-session guards also prevent extra fallback messages. No settings, provider trust policies, or native goal files are rewritten.
