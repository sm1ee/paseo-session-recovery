session-recovery tracks running Paseo turns and continues unfinished sessions after the daemon restarts. An optional goal mode also continues a session when a normal turn ends with its goal still active. It starts tracking with the next observed turn; an existing session can be included with Watch this session's goal in the Command Center.

![Recovery and goal settings](assets/goal-settings.png)

Automatic recovery is on by default for main sessions, with a 60-second delay, up to three attempts per interruption, and a 24-hour recovery window. The delay doubles after each attempt, up to 15 minutes. Subagent recovery and retries for recognized temporary provider errors can be enabled separately.

The recovery screen shows scheduled continuations, goal states, sessions that need review, exclusions, and recent activity. You can preview a continuation before sending it manually, dismiss a candidate, or exclude a session from future recovery. Direct stops, questions, and approvals are excluded from automatic recovery. Uncertain delivery requires checking the conversation.

Goal continuation is off by default. Enable it in settings and choose a delay and a per-objective continuation limit, initially 60 seconds and 10 continuations. Codex uses its official goal lookup API through a local subprocess running the configured provider command. The subprocess only initializes and reads goal state. OMP and compatible Pi goal tools use structured conversation results; OMP goal update events are included. A provider must expose a supported goal state. Paused, blocked, complete, cleared, limited, and unknown goals do not continue automatically. The plugin cannot verify that a goal marked complete was actually achieved.

Recovery starts a new turn in the existing conversation using its current provider and settings. The message asks the agent to check existing work before repeating commands or external actions. It cannot restore an interrupted process. Lifecycle events are best effort, so an interruption cannot always be classified. Paseo 0.11 and 0.12 have no atomic send-if-idle request; the plugin rechecks before submission, but a concurrent action can still race it.

Requires a macOS or Linux daemon running stable Paseo 0.11.4 through 0.12.x and a provider with saved history. Background workspaces are included on 0.12. Only Paseo-managed sessions are covered. The paired session-janitor 0.1.2+ protects pending recovery and goal continuation from cleanup; other cleaners do not read those protections. Goal mode reads conversation records in memory and stores only a fingerprint, state, and continuation count alongside session metadata. Local files use owner-only permissions. Continuations use the existing session and provider, with normal provider usage and billing.
